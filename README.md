# anti-afk-media-controller
Reverse engineering of Page Visibility API. Prevents media auto-pause on inactive tabs. Pure JS prototype overriding.
# 🎬 Anti-AFK Media Controller

**Управление медиа-потоком и обход детекции неактивности вкладки (Page Visibility API) на стороне клиента.**

## 📖 О проекте

Этот исследовательский пет-проект создан для изучения того, как современные веб-приложения отслеживают активность пользователя, и как работают механизмы управления медиа-элементами (`<video>`, `<audio>`) в браузере.

Многие стриминговые платформы и медиа-сервисы используют **Page Visibility API** для приостановки воспроизведения, когда вкладка становится неактивной (сворачивается, теряет фокус и т.д.). Данный скрипт демонстрирует, как можно перехватить управление медиа-элементами и скрыть факт потери фокуса от веб-приложения.

## ⚙️ Как это работает под капотом

Скрипт использует продвинутые возможности JavaScript для работы с прототипами и DOM-событиями:

1. **Спуфинг (подмена) Page Visibility API:** 
   Свойства `document.hidden` и `document.visibilityState` переопределяются через `Object.defineProperty`, заставляя сайт думать, что вкладка всегда активна.
2. **Блокировка событий неактивности:**
   События `visibilitychange`, `blur` и `pagehide` перехватываются на фазе захвата (`capture phase`) с помощью `stopImmediatePropagation()`, предотвращая их обработку скриптами сайта.
3. **Перехват методов `HTMLMediaElement`:**
   Методы `play()` и `pause()` на уровне прототипа подменяются. В зависимости от установленного режима, вызовы паузы игнорируются, а вызовы воспроизведения принудительно повторяются.
4. **"Призрачный" медиа-элемент (Ghost Video):**
   Создается скрытый элемент `<video>` с пустым MP4-источником (base64). Это используется как "приманка" для скриптов, которые проверяют наличие активного медиа-потока на странице.
5. **Heartbeat-механизм:**
   `setInterval` каждые 500 мс проверяет состояние всех медиа-элементов на странице и принудительно удерживает их в нужном состоянии (play/pause).

## 🛠 Управление

Скрипт поддерживает горячие клавиши для ручного переключения режимов:
* `Alt + P` — Принудительное воспроизведение (режим Anti-Pause).
* `Alt + S` — Принудительная пауза (возврат к стандартному поведению).

*(Скрипт игнорирует нажатия, если фокус находится в полях ввода `input` / `textarea`).*

## 🧠 Чему я научился (Ценность для инженерии)

Этот проект помог мне на практике разобраться в следующих темах:
* **Прототипное наследование:** Понимание того, как работают `prototype`, `call` и `this` при переопределении нативных методов браузера.
* **Безопасность на клиенте (Client-Side Security):** Демонстрация того, почему нельзя доверять `document.hidden` или событиям фокуса для критически важной логики (например, учета рабочего времени или античит-систем). Любую клиентскую проверку можно обойти.
* **Архитектура веб-плееров:** Понимание того, как сайты оптимизируют трафик и управляют состоянием плеера.
* **Работа с Media API:** Тонкости работы с `HTMLMediaElement`.
